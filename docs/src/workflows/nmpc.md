# 20 Hz NMPC expert

The privileged rendezvous expert is implemented in `srb/nmpc/`.  Its public
state is `State13 = [r_L, v_L, q_LB, omega_BI_B]`; the main translational
model is HCW/CW and the attitude model is scalar-first quaternion kinematics
with rigid-body Euler dynamics.  The global control grid is fixed at 20 Hz:

```text
Ts = 0.05 s, N = 20, horizon = 1.0 s, RK4 = 5 x 0.01 s substeps
action blocks = (3, 3, 3, 3, 2, 2, 2, 2)
```

`IpoptOracle` is the high-accuracy reference solver.  `AcadosExpert` uses
acados with the HPIPM QP backend for the production path.  `SafetyAllocator`
is a separate OSQP projection layer and never turns an infeasible projected
command into an expert label.  The current SRB Cubesat is exposed only by
`SrbAdapter` as an explicitly labelled rank-5 contrast; it is not the source
of the main 6-D labels.

The YAML boundary is `load_nmpc_config()` in `srb/nmpc/config.py`. It validates
the fixed 20 Hz, 13-state, 16-channel contract and returns the `TaskParams`
passed to both backends together with the solver settings. The smoke,
backend-comparison, and realtime scripts all use this loader.

SRB also contains an opt-in full-rank actuator variant:
`srb/rendezvous_16rcs` and `srb/rendezvous_16rcs_visual`. It reuses the
Cubesat rigid/visual asset but configures the exact 16 one-sided RCS lines and
the SRB thrust-vector sign convention. `Srb16Adapter` accepts a command as a
valid 6-D label only when the executed matrix residual is below the gate. The
original `srb/rendezvous` task remains the legacy 8-thruster rank-5 contrast.

This actuator variant does not silently change SRB's underlying physics:
current SRB rendezvous remains the zero-gravity/free-floating environment.
The paper's main HCW/CW trajectories are still generated by the standalone
NMPC plant; the 16-RCS SRB task is the executable actuator/integration path.
An HCW-enabled SRB environment would be a separate dynamics integration step.

For an FOV-enabled episode, `target_point_T_m` denotes the service hover point
while `camera_target_point_T_m` denotes the observed target feature (the
target-body origin by default).  The feature is rotated into LVLH at each
timestamp, so minimum depth remains meaningful at the terminal hover point.

## acados installation used by this checkout

The source tree is pinned to acados `v0.5.5`, revision
`59d93e17d2985fdd73fc58b8a83ed8f83a024171`.  It was built on Linux with
shared libraries and generic BLASFEO/HPIPM targets:

```bash
git clone --branch v0.5.5 https://github.com/acados/acados.git third_party/acados
git -C third_party/acados submodule update --init --recursive \
  external/blasfeo external/hpipm tera_renderer
cmake -S third_party/acados -B third_party/acados/build \
  -DCMAKE_BUILD_TYPE=Release \
  -DACADOS_INSTALL_DIR="$PWD/third_party/acados" \
  -DBUILD_SHARED_LIBS=ON \
  -DBLASFEO_TARGET=GENERIC -DHPIPM_TARGET=GENERIC \
  -DACADOS_WITH_QPOASES=OFF -DACADOS_WITH_OSQP=OFF
cmake --build third_party/acados/build --parallel
cmake --install third_party/acados/build
```

The acados Python interface is installed into the Isaac Sim Python
environment, and the `t_renderer` release binary is placed at
`third_party/acados/bin/t_renderer`.  Always use the SRB wrapper so that
`ACADOS_SOURCE_DIR` and `LD_LIBRARY_PATH` point at this checkout:

```bash
./srb_0.0.5_env.sh -- /home/ubuntu/isaac-sim-4.5/python.sh -c \
  "import casadi, acados_template; print(casadi.__version__); print(acados_template.__file__)"
./srb_0.0.5_env.sh -- /home/ubuntu/isaac-sim-4.5/python.sh \
  scripts/smoke_test.py --config configs/default.yaml --skip-ipopt
```

For a full-rank SRB actuator rollout, select the explicit task ID:

```bash
./srb_0.0.5_env.sh srb agent eval --headless \
  -e rendezvous_16rcs env.num_envs=1
```

The smoke check must construct and solve one acados OCP with status 0 and an
independently accepted trajectory.  CasADi 3.8.0 currently emits an acados
template compatibility warning; it is recorded as an environment caveat and
is not suppressed by the code.

## Runtime measurement

Use the hot-loop benchmark after solver generation:

```bash
./srb_0.0.5_env.sh -- /home/ubuntu/isaac-sim-4.5/python.sh \
  scripts/benchmark_realtime.py --iterations 100
```

The report separates acados `time_tot` from the end-to-end wall time.  The
20 Hz acceptance gate is applied to endpoint wall time (`p99 <= 40 ms`) and
the safety QP (`p99 <= 2 ms`), so Python validation and host scheduling are
not hidden inside an internal solver-only number.

## Optional serialization support

The Isaac Sim Python environment already provides NumPy 1.26.0, pandas 2.3.3,
h5py 3.16.0, and PyYAML 6.0.1. It did not provide a Parquet engine, so this
checkout installs only `pyarrow==18.1.0` with `--no-deps` into the ignored,
repository-local directory `third_party/python/`. The SRB wrapper prepends
that directory to `PYTHONPATH`; Isaac Sim's global `site-packages` is not
modified. Recreate the support with:

```bash
./srb_0.0.5_env.sh -- /home/ubuntu/isaac-sim-4.5/python.sh -m pip \
  install --no-deps --only-binary=:all: \
  --target "$SRB_ROOT/third_party/python" \
  -r requirements-nmpc-isolated.txt
```

The same isolated directory contains `Cython==3.0.12` because it is an
acados-template declared dependency. The production expert still uses the
default shared acados C interface (`with_cython=False`), so Cython is not on
the hot path; keeping it isolated makes the optional Cython interface
available without changing Isaac Sim's packages. CasADi 3.8.0 remains the
existing Isaac Sim package: acados emits a compatibility warning, but changing
CasADi globally would be a larger and unnecessary SRB environment change.

Verify both serialization formats through the wrapper:

```bash
./srb_0.0.5_env.sh -- /home/ubuntu/isaac-sim-4.5/python.sh -c \
  "import h5py, pandas, pyarrow; print(h5py.__version__, pandas.__version__, pyarrow.__version__)"
```
